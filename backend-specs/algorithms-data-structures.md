# Backend Algorithms & Data Structures Spec — 计算设计

以下任务**必须**进行算法与数据结构分析：搜索、排序、去重、分组、
图遍历、树遍历、BOM 展开、工作流、排程、Top K、区间查询、依赖解析、
权限继承、缓存设计、大批量处理、相似度检索、限流、分片。

## 1. 数据结构选择决策表

| 访问模式 | 选择 |
|---|---|
| 顺序遍历 / 索引访问 / 量小 | Array/List |
| Key 查询 / 分组 / 索引 / Join 预加载 | HashMap（把 O(n×m) 的嵌套 find 改为 O(n+m) 的 Map 预载） |
| 去重 / 成员判断 / visited | HashSet |
| DFS / 撤销 / 表达式解析 | Stack（深度大用显式栈防溢出） |
| BFS / 调度 / 滑动窗口 / 层级遍历 | Queue/Deque（禁止 array.shift() 当队列——O(n)） |
| Top K / 优先级 / 最短路径 / 多流合并 | Heap（1 亿取 Top 100：O(n log k) 堆，不 O(n log n) 全排） |
| 层级 / 权限继承 / 区间 | Tree（理解数据库 B+Tree 行为，不自造） |
| 前缀搜索 / 自动补全 / 敏感词 | Trie（数据少时 HashMap 可能更简单） |
| 工作流 / 依赖 / BOM / 路线 | Graph（判有向/环/加权/稀疏） |
| 大规模整数集合 / 签到 / 活跃位 | Bitmap（1 亿用户活跃 ≈ 1 bit/人） |
| 近似成员预判 | Bloom Filter |
| 近似基数统计（UV/去重计数） | HyperLogLog |
| 有序集合 / 排名 | Skip List |
| 全文搜索 | Inverted Index（`%keyword%` 替代不了） |
| 分布式缓存分片 | Consistent Hashing（虚拟节点/热点/副本） |

禁止默认用 Array 解决所有问题。

## 2. BFS vs DFS

| 需求 | 选择 |
|---|---|
| 最少步骤 / 最近节点 / 无权最短路径 / 层级输出 | BFS（队列，O(V+E)/O(V)） |
| 全路径 / 回溯 / 环检测 / 拓扑排序 / 连通分量 | DFS（递归或显式栈） |
| 加权最短路径 | Dijkstra 等 |
| 深度极大 | 显式栈 DFS（防递归栈溢出） |

图遍历必须维护 visited 集合，除非结构保证无环。

## 3. 排序选择

优先语言标准库/数据库 ORDER BY + 索引。需要稳定 → 稳定排序；接近有序 →
Timsort 类；固定范围整数 → Counting Sort；超内存 → 外部排序；Top K →
Heap（不默认全量排序）；多有序流合并 → 归并。禁止随意手写快排。

## 4. 二分查找（不只看"找数字"）

适合有序数组/单调条件：第一个大于等于目标的时间、最小满足容量、
最大允许批次、最短完成时间。前提：搜索空间单调。O(log n)。

## 5. Bloom Filter 使用规则

仅用于**允许假阳性**的预过滤：防缓存穿透、大规模成员预判、URL 去重
前置、黑名单预过滤。**禁止**用于权限/金额/数据是否真实存在的唯一依据。
使用前必须估算：元素数量、假阳性率、位数组大小、哈希函数数、扩容重建、
多实例同步、删除需求、冷启动。

## 6. 复杂度：五类成本（不只 CPU）

1. **CPU**：O(1)/O(log n)/O(n)/O(n log n)/O(n²)
2. **内存**：一次加载 500 万行，即使 O(n) 也可能 OOM
3. **数据库**：扫描行数、索引命中、回表、排序、临时表、锁、事务时长、
   往返次数——循环查库的真实成本常比算法复杂度更严重
4. **网络**：一次批量请求 vs 循环 1000 次远程调用；RTT、payload、
   序列化、超时、并发、限流
5. **分布式协调**：分布式锁、共识、跨服务事务、重试、消息重复、时钟偏差、分区

禁止只说"O(1) 所以快"。

## 7. 避免清单

- O(n²) 嵌套查找（循环内 .find/.includes/.filter）
- 循环查数据库 / 循环调远程服务（N+1）——用批量 + JOIN + Promise.all
- 一次加载全部大数据；全量排序后只取少量（Top K 用堆）
- 无界递归 / 无界队列 / 无界缓存 / 无界并发

## 8. 优化顺序

保证正确性 → 确认数据规模与性能目标 → Profiling 找瓶颈 → 优化算法与
数据结构 → 减少 DB/网络 I/O → 批处理与并发池 → 缓存/索引/预计算 →
基准测试验证。未经基准测试不得声称"已优化"。

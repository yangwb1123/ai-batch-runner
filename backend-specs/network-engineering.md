# Backend Network Engineering Spec — 超时分层/客户端复用/重试/背压

## 1. 请求生命周期（不能只设一个总 Timeout）

```
DNS → TCP → TLS → Connection Pool → Request → Server Processing → Response → Deserialization
```

必须考虑：DNS 超时、连接超时、TLS 握手超时、请求头超时、响应读取
超时、**总截止时间（Deadline）**、连接池等待时间。

## 2. HTTP 客户端规范

必须：复用客户端与连接池、设置池大小、超时、响应体大小上限、正确关闭
响应流、限制重定向、校验证书、受控重试、传播 Trace Context、支持取消。
**禁止每次请求创建新客户端**（连接池失效）。

## 3. 重试矩阵

| 错误 | 重试 |
|---|---|
| 连接重置/超时/某些 429/502/503/504 | 可重试（指数退避 + 随机抖动 + 最大次数 + 总时间预算） |
| 400/401/403/业务校验失败 | 不重试 |
| 非幂等操作且无幂等机制 | 不重试 |

**重试是负载放大器**：明确唯一重试责任层、总预算、Deadline 传播、
幂等、防重试风暴（多层各自重试 3 次 = 81 倍放大）。

## 4. 端到端超时预算

用户总预算 2s ≠ 每个下游都 2s：网关 2s / 订单 1.7s / 库存 500ms /
支付 800ms + 处理/序列化/网络抖动余量。传播 Deadline，不逐层重置。

## 5. 流式处理与背压

大文件/大查询/大消息禁止全部载入内存：Stream / Iterator / Generator /
Cursor / Channel / Async Iterator / Reactive Stream。
上游速度 > 下游处理速度时必须限流（最大并发/队列长度/拒绝策略/
生产者减速/超载返回码）——否则内存增长 → 延迟恶化 → 超时 → 重试 →
**雪崩**。

## 6. 禁止清单

- 循环内远程调用（N+1 网络：批量 + Promise.all/并发池）
- 无超时请求；无限重试；无界并发
- 不关闭响应体；大型响应全部读入内存
- 在数据库长事务内做不受控网络调用
- 忽略 429 的 Retry-After

## 7. 集成外部系统

第三方 SDK 用 Adapter 隔离；定义每个依赖的超时/重试/熔断/降级/告警
（故障时行为明确，不静默失败）；Trace Context 贯穿。

# 后端设计智能 04：体验架构（Experience Architecture）

> 后端架构也有 UX 思维：体验要求 500ms 打开，架构必须响应体验预算。

## 1. 体验预算（UX Budget）反推架构

| 体验目标 | 架构推导 |
|---|---|
| 详情 500ms 打开 | Read Model / CQRS（不 10 表 join） |
| 仪表盘即时 | 预聚合统计端点 + Cache |
| 输入即搜 | 搜索索引（全文/前缀）+ 缓存 + 限流 |
| 实时异常 | 事件流/WebSocket + 增量快照 |
| 大列表平滑 | 游标分页 + 只读快照 |

**规则**：先定体验预算（每页面延迟目标），再选架构模式——模式服务预算，不凭空设计。

## 2. CQRS / Read Model 决策

何时用（不是默认）：
- 读模型与写模型形态差异大（详情聚合 vs 原子写）
- 高频读 + 低频写
- 查询复杂（多表聚合）

何时不用：
- CRUD 简单场景（YAGNI——三次原则）

## 3. 缓存策略

- 读缓存：聚合端点（客户上下文、仪表盘）
- 失效：事件驱动（写后发事件 → 缓存失效/重建）
- 一致性：可接受最终一致（体验数据）；关键数据（金额/库存）用版本校验

## 4. 异步体验（长任务）

上传/导出/批量处理 > 2s：

```
接受（202 + 任务 id）→ 进度端点 → 完成/失败回调（事件）
```

**规则**：长任务永不同步阻塞请求；页面轮询/事件推送进度；失败可重试（幂等）。

## 5. 检查清单

```
□ 每个页面是否有延迟预算？
□ 复杂聚合是否 Read Model/物化（而非实时 join）？
□ 高频端点是否有缓存 + 事件失效？
□ 长任务是否异步 + 进度 + 幂等重试？
□ 实时场景是否事件流？
□ 架构模式是否服务体验预算（而非堆技术）？
```

# 后端设计智能 01：体验驱动 API（Experience-Driven API）

> 前端与后端不是接口连接，而是业务闭环。
> API 服务的是体验，不是数据表。

## 1. 页面交互决定 API 形态

用户搜索客户时体验期望"输入即出现关联上下文"：

```
输入: 华为
→ 华为技术有限公司 · 订单 238 · 金额 500万 · 风险 低
```

对应 API 不是 `GET /customers?name=abc`（返回裸列表），而是**聚合上下文端点**：

```
GET /customer/search?q=华为
→ {
    customer: { id, name },
    context: { orders: 238, amount: 5000000, risk: "low" }
  }
```

**规则**：设计 API 前先写"用户操作 → 页面响应"的场景卡，接口形态从场景卡推导。

## 2. 场景卡模板（每个端点一张）

```
端点: GET /customer/search
体验: 输入即出现名称 + 订单数 + 金额 + 风险
响应延迟: < 300ms
调用方: 客户选择器（每次击键）
数据来源: customer + orders 聚合（read model / cache）
```

## 3. 交互模式 → API 模式映射

| 交互模式 | API 模式 |
|---|---|
| 输入即搜（autocomplete） | 聚合搜索端点 + 缓存 + 限流 |
| 列表渐进加载 | 游标分页（next_token）+ 每页固定大小 |
| 乐观更新 | 幂等键 + 版本号（并发冲突可回滚） |
| 批量操作 | 批量端点 + 部分成功明细（3 成功/1 失败+原因） |
| 实时异常 | 事件流/WebSocket + 增量快照 |
| 详情 500ms 打开 | Read Model / 物化视图（不 10 表 join） |
| 仪表盘大数字 | 预聚合统计端点（counter/rollup 表） |

## 4. API 分层（体验服务链）

```
聚合端点（服务页面） → 领域端点（服务业务） → 原子端点（服务集成）
```

页面只调聚合端点（1 次往返），领域/原子端点供内部与集成使用。

## 5. 检查清单

```
□ 每个页面交互是否映射到 API 形态（场景卡）？
□ 高频页面是否 1 次往返（聚合端点）？
□ 搜索是否有上下文聚合（而非裸列表）？
□ 批量操作是否返回部分成功明细？
□ 乐观更新是否有幂等键 + 版本号？
□ 详情/大数字是否有 Read Model/预聚合？
□ 实时场景是否有事件流而非轮询？
```

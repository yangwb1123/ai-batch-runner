# 后端设计智能 08：分发智能（Distribution Intelligence）

> 没有分发的软件只是某台电脑里的代码。分发是信息结构从"存在"
> 走向"产生影响"的过程——与光传播能量、语言传播思想同构。
> 软件传播的是"降低不确定性的能力"与"更高级的控制能力"。

## 1. 设计即分发（Distribution by Design）

高手从第一天考虑传播路径，不是最后补营销：

- 网络效应：一人使用 → 邀请 → 价值随用户数增长（微信）
- 生态：代码 → Star → Fork → 贡献者 → 社区（GitHub）
- 复用：模块化 + 可移植（配置即分发）

**设计检查**：产品是否内置传播机制（分享/邀请/模板/API/生态接口）？

## 2. 分发对象分层

| 层 | 内容 | 机制 |
|---|---|---|
| 用户 | 使用价值 | 应用/登录/模板 |
| 团队 | 协作价值 | 共享配置/邀请 |
| 组织 | 流程价值 | 部署包/镜像/迁移脚本 |
| 生态 | 扩展价值 | API/插件/开放契约 |

## 3. AI 时代：软件从产品到能力

```
以前：开发公司 → 应用商店 → 用户安装
未来：问题出现 → 用户描述 → Agent 生成 → 立即使用 → 分享
```

- 软件分发 → **能力分发**（Agent 技能/规则/规范/模板）
- 每个 Agent 生成物都应可分享（规范文件/流水线 YAML/检查器）

## 4. 分发质量的工程保障

被分发的东西必须可复现、可验证、可接手：

- 配置即代码（声明式，非操作手册）
- 自带验证（自检/测试/门禁随分发物一起）
- 文档完整（README + ADR——知识维护）
- 版本可追溯（变更日志）

## 5. 检查清单

```
□ 产品是否设计传播路径（网络效应/分享/生态）？
□ 分发物是否可复现（配置即代码）？
□ 是否自带验证（自检/测试）？
□ 是否可接手（文档/ADR）？
□ 是否版本可追溯？
□ Agent 生成物是否可分享（规范/流水线/门禁）？
```

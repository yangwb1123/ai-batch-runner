# Agent Guardrails — AI 特有护栏（防幻觉 + 变更控制 + 边界纪律）

## 1. 禁止（幻觉红线）

- 虚构不存在的库 API、假设项目存在某文件、使用过时版本语法
- 编造测试通过结果 / 命令输出 / 性能数据
- 自动改变业务规则；未检查项目依赖就引入新框架
- 用伪代码填充核心逻辑；用 TODO 冒充实现
- 创建名称正确但无法编译的接口；编造官方类型定义

必须：先搜索现有代码 → 确认依赖版本 → 查看官方类型定义 → 优先复用
现有模式 → 运行实际命令 → 根据错误修复 → 明确标注未验证内容。

## 2. 变更范围控制（每个任务输出变更半径）

直接修改文件 / 间接影响模块 / 公共接口变化 / 数据库变化 / 事件变化 /
配置变化 / 部署变化 / 回滚方式。

禁止为小功能：重构整个目录、更换 ORM/框架、引入消息队列/微服务、
改写所有公共类型。计划外修改必须说明理由。

## 3. 不要为了 DRY 牺牲边界

两个上下文看似相同的代码，业务语义可能不同（销售价格 vs 采购成本
vs 财务结算——都是"金额计算"但变化原因不同）。**业务重复比错误抽象
更容易修复**。抽象门槛：至少两个真实跨业务使用方 + 稳定语义 + 变化轴。

## 4. 性能优化纪律

禁止无数据依据的"优化"（先加 Redis/开线程/加机器/上复杂结构）。
顺序：先测量 → 找瓶颈 → 优化算法 → 减 I/O。未经基准测试不得声称
"已优化"。

## 5. 完成定义（不得只凭代码阅读宣布完成）

- 验证命令实际运行：lint/typecheck/test/build/与改动相关的集成测试
- 无法运行的命令必须列出：命令、原因、未验证风险
- 不伪造：测试结果、命令输出、覆盖范围
- 未解释的警告不得存在；Git diff 无无关修改

# Business UI Contract — 业务 UI 契约规范

> 目的：Agent 生成业务页面时，先做**业务理解 → 角色理解 → 任务建模 →
> 状态机 → 信息优先级 → 交互路径 → 几何构图 → 视觉表达 → 代码**，
> 而不是"读 Prompt → 选组件 → 写代码"。这是评审角色的裁决依据之一。

## 1. 页面定义（不是组件拼装）

```
Page = Role × Scenario × Goal × Task Flow × Business Object
       × Data State × Permission × Risk × Device Context
```

生成前必答：

| 问题 | 必须输出 |
|---|---|
| 谁在什么场景使用 | 角色 + 场景 |
| 要完成什么任务/判断 | 核心任务 + 决策点 |
| 哪些数据影响判断 | 数据优先级（critical/secondary/on_demand） |
| 哪些操作最常用/风险最高 | 操作矩阵（frequency/importance/risk） |
| 业务对象状态机 | 状态转换图 + 每状态可执行操作 |
| 操作后系统如何反馈 | 成功/失败/部分成功/恢复 |

## 2. 角色差异

同一业务对象不同角色看到的页面不同（排程员 vs 主管 vs 物料员 vs 审计员）。
**禁止**所有角色同一页面只隐藏按钮。角色化包括：信息优先级、默认筛选、
首页入口、数据密度、操作路径、告警阈值、解释方式。

注意：**前端隐藏 ≠ 权限控制**——后端必须做 RBAC/业务规则校验。

## 3. 操作矩阵（位置由频率×重要性×风险决定）

| 组合 | 呈现方式 |
|---|---|
| 高频·高重要·低风险（查询/保存/扫码确认） | 直接可见、靠近工作区、支持快捷键 |
| 低频·高重要·高风险（作废/撤销/删除/关账） | 隔离放置、明确文字、二次确认、影响预览、原因必填、审计、可恢复 |
| 高频·低重要（展开/复制/刷新） | 局部工具栏，不抢视觉重心 |

## 4. 状态空间（禁止只设计成功路径）

每个页面至少覆盖：初始 / 加载（局部优先）/ 空数据（区分真无/筛选无/无权）/
部分成功 / 陈旧数据（显示更新时间、高风险操作超时阻断）/ 无权限（禁用并
解释）/ 前置条件不满足 / 并发冲突（展示双方修改+修改人+时间+选择保留/合并/
重载）/ 超时 / 可撤销 / 不可恢复失败（诊断信息）。

## 5. 数据可信度

- 区分：0 / 空值 / 未知 / 未计算 / 不适用 / 无权查看 / 获取失败——禁止全显示 "-"。
- 每个关键指标声明：来源 / 口径 / 单位 / 时间范围 / 更新时间 / 精度。
- 区分**业务事实**（交期 8/12）、**系统计算**（预计 8/14，附依据）、
  **AI 建议**（置信度 + 人工确认 + 采纳记录）——AI 建议 ≠ 事实。

## 6. 交互即状态转换

每个异步操作定义：触发 → 前置校验 → 处理中 → 成功 → 失败 → 重试 →
防重复（幂等）→ 必要时撤销。拖拽等交互必须表达：合法目标高亮、非法禁用、
冲突预览、影响范围、放置确认、失败回滚、撤销、审计。

## 7. 错误处理顺序

预防（合法目标/输入约束）→ 限制影响（高风险批量预览/陈旧数据阻断）→
解释（发生了什么/为什么/哪些成功/用户能做什么）→ 恢复（重试/保留输入/
失败清单/撤销/Trace ID）。

## 8. 反模式（评审直接 FAIL 项）

- 按 API 字段列表生成表单顺序（Database Schema ≠ Information Architecture）
- 所有列表页四张 KPI 卡片 + 图表 + 表格 + 右上角按钮
- 所有编辑用 Modal；所有状态只换 Tag 颜色；所有操作放右上角
- 只生成成功路径，无加载/空/失败/权限/并发状态
- 默认值无理由（默认 7 天/按创建时间排序/默认启用）
- 无业务语义的动画（卡片飞入/烟花/持续闪烁）
- 真实数据分布（超长文本/负数/大数字/慢接口/并发）未测试
- 对演示数据好看、5 万行不可用的页面

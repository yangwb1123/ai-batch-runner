# 设计智能规范 02：色彩智能（Color Intelligence）

> 颜色不是"美化"，是产品认知系统的一部分。
> 禁止"主色+辅色+按钮色"的机械三元组；必须走
> 场景 → 用户心理 → 信息权重 → 品牌气质 → 色彩语言 → 交互反馈。

## 1. 页面风格决定颜色策略（先判断再选色）

生成颜色前必须判断：

- 产品类型（Enterprise / SaaS / AI / Creative / Dashboard）
- 用户场景（日常办公 / 决策 / 监控 / 创作）
- 使用时间（白天工作 vs 夜间监控）
- 情绪目标（可信 / 活力 / 未来感 / 专注）
- 信息密度（高密度监控 vs 低密度引导页）

## 2. 企业系统颜色范式（Enterprise / ERP / OA）

- **目标**：专业、稳定、高效、可信
- **主色**：深蓝、藏青、灰蓝（避免亮蓝/紫色）
- **辅助**：青色、绿色（低调的功能色）
- **背景**：浅灰 + 白（#F5F7FA 类）
- **参考**：SAP Fiori / Microsoft Fluent / ServiceNow

## 3. SaaS 产品颜色范式

- **目标**：活力、现代、易用
- **策略**：单一品牌主色 + 语义色系统（避免彩虹）
- **可选 Gradient System**（仅 hero/重点区）：紫→蓝（#6366F1 → #8B5CF6）
- **适用**：AI 产品、创业产品、SaaS 首页

## 4. AI 产品视觉语言

- **Aurora Gradient（极光渐变）**：蓝 + 紫 + 青 + 粉，表现智能/科技/未来感
- 深色为主（Dark Surface System）+ 渐变点缀
- 玻璃拟态（Glass Card）+ Glow 光晕

## 5. 数据大屏颜色系统（语义色，禁止随机）

**必须建立语义色**——用户不读文字，只看颜色：

| 语义 | 颜色 | 含义 |
|---|---|---|
| 正常 | 🟢 绿 | 运行中/通过 |
| 警告 | 🟡 黄 | 等待/接近阈值 |
| 异常 | 🔴 红 | 故障/失败 |
| 信息 | 🔵 蓝 | 中性信息 |

**规则**：图表/状态颜色必须来自语义 token（success/warning/danger/info），禁止每图随机配色。

## 6. Dark Surface System（深色模式）

不是"黑背景+白字"，是**层级化表面**：

```
Background #0B0F19
  ↓ Surface   #111827
  ↓ Card      #1F2937
  ↓ Floating  #374151
```

- 深色下语义色需**提亮**（danger #B91C1C → #F87171 类），保证对比度 ≥ 4.5:1（文字）/ ≥ 3:1（图形）
- 徽章文字色按**渲染后底色亮度**选黑/白（不能按语义色本身亮度——浅底白字是经典 bug）

## 7. Glass + Gradient 组合（AI 工作台）

```
Gradient Background
  → Glass Card（Blur + 半透明）
  → Glow（光晕点缀）
```
仅用于 AI/创意产品；企业系统克制使用。

## 8. 多彩系统（Multi Color System）

- 项目管理/分类场景（Notion/Linear/Jira）：颜色成为**分类语言**（项目 A 蓝、B 紫、C 绿）
- 规则：颜色必须对应**可区分的语义**，且色弱友好（颜色 + 图标/文字双编码）

## 9. 情绪设计（Emotional Design）

| 产品 | 情绪 | 颜色 |
|---|---|---|
| 财务系统 | 可信、安全、专业 | 蓝 + 灰 + 绿（禁彩虹） |
| 创意工具 | 创造欲 | 渐变、高饱和、动态 |
| 游戏化系统 | 兴奋、奖励 | 亮色 + 动画 + 反馈 |

## 10. 自动生成 Design Token（生成页面前的第一步）

```json
{
  "theme": "AI SaaS",
  "colors": {
    "primary": "#6366F1",
    "secondary": "#8B5CF6",
    "success": "#10B981",
    "warning": "#F59E0B",
    "danger": "#EF4444",
    "info": "#3B82F6"
  },
  "gradient": { "hero": "purple-blue" },
  "semantics": { "ok": "success", "warn": "warning", "error": "danger" }
}
```
然后所有组件、状态、图表引用 token——禁止散落字面量。

## 11. 颜色 + 交互结合（颜色不是静态）

| 状态 | 颜色 |
|---|---|
| 上传开始 | 灰 |
| 处理中 | 蓝（渐变/动效） |
| 完成 | 绿 |
| 失败 | 红 |

交互颜色与状态语义绑定，随状态流转。

## 12. Icon + Color 联合语义（双编码）

人脑识别图形快于文字：

- ❌ 文字："订单异常 12"
- ✅ 🟢 正常 230 / 🟡 等待 8 / 🔴 异常 12

**规则**：状态展示必须"颜色 + 图标 + 文字"三编码（至少双编码），色弱用户与屏幕阅读器可理解。

## 13. 检查清单（UX Review）

```
□ 是否统一色彩语言（token 单一来源）
□ 是否符合产品定位（企业=克制 / SaaS=活力 / AI=渐变深色）
□ 是否滥用渐变（仅 hero/重点区）
□ 是否有视觉焦点（颜色强调 ≤3 处）
□ 是否有颜色语义（状态/图表用语义 token）
□ 是否支持 Dark Mode（表面层级 + 语义色提亮 + 对比度）
□ 是否符合品牌气质
□ 是否减少文字依赖（图形化表达）
□ 交互状态色是否流转（灰→蓝→绿→红）
```

## 14. 禁止清单

- 随机颜色 / 默认蓝色后台（不分析场景直接用蓝）
- 过度渐变（全页面渐变 = 无焦点）
- 无意义装饰色
- 颜色作为唯一信息编码（必须双编码）
- 语义色在深色模式未提亮

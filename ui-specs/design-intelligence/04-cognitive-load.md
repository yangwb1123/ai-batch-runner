# 设计智能规范 04：认知负担与心理模型（Cognitive Load）

> 不要让用户思考系统，而让系统理解用户。
> 设计不是给机器看的，是给人的大脑看的。

## 1. 减少记忆负担

❌ 让用户记忆：订单编号、物料编码、客户编号、状态码（机器语言）

✅ 系统自动推理：
```
输入: 华为
自动提示: 华为技术有限公司 · 最近订单 238 个 · 未交付 5 个 · 风险 2 个
```

**检查**：这个操作需要用户记忆吗？能否自动推理/补全/提供上下文？

## 2. 匹配用户心理模型（Mental Model）

- 计算机模型：folder/file/permission/path
- 人的模型：我的资料/最近使用/重要文件/项目

**规则**：不暴露技术模型，匹配人的思维模型（Notion 的知识空间 > Windows 的文件夹）。

## 3. 渐进式展示（Progressive Disclosure）

不一次展示所有东西（100 字段/50 按钮/20 状态 = 认知灾难）。

```
第一层：核心信息（头像/姓名/状态/最近活动）
第二层：常用操作
第三层：高级配置（权限/日志/配置——折叠）
```

## 4. 错误预防（Error Prevention）

高手不是设计错误提示，而是避免用户犯错：

- ❌ 删除订单 → "确认删除？"
- ✅ "该订单已经生产完成，删除会影响生产记录和财务记录，建议关闭订单"

**检查**：用户可能犯什么错？如何提前阻止（确认对话框带影响说明、危险操作色编码、破坏性操作要求输入确认文本）？

## 5. 空状态是产品教学（Empty State）

❌ "暂无数据"（死页面）

✅
```
👋 欢迎使用
你可以：+ 创建第一个项目  或  导入已有数据
```

空状态 = 引导下一步 + 展示产品价值。

## 6. 用户成长路径（User Journey）

考虑 Day 1 / Day 7 / Day 30：
- 新用户：引导、示例、空状态教学
- 熟练用户：快捷入口、最近使用、键盘快捷键
- 高级用户：批量操作、自定义、API

## 7. 信任感（Trust）

企业系统必须让用户感到可靠：

- 操作后：`✓ 已保存 · 刚刚 · 操作人: 张三`（可审计）
- AI 建议：`AI 建议 · 依据: 过去 30 天数据 · 可信度 92%`（可解释）

**规则**：危险操作要审计线索；AI 输出要依据与置信度。

## 8. 上下文感知（Context Awareness）

未来 UI 理解：谁登录？现在做什么？历史行为？当前任务？

- PMC 首页：生产异常
- 老板首页：利润风险

**规则**：同一页面可按角色/上下文调整焦点（动态优先级）。

## 9. 心流体验（Flow State）

减少中断：审批流（打开待办 → 看到关键风险 → 快速决策 → 一个动作完成）而不是（打开页面 → 点击审批 → 填写意见 → 提交 → 刷新）。

**检查**：用户完成任务需要几步？每步是否必要？

## 10. 人机协同（Human + AI）

AI 增强而非替代：AI 分析 → 人确认 → 系统执行。

```
AI: 发现异常——供应商价格上涨 15%，建议重新询价
人: 确认
系统: 执行
```

## 11. 认知负担检查清单

```
□ 操作需要用户记忆吗？（自动补全/推荐）
□ 是否符合用户心理模型？（非技术模型）
□ 是否渐进式展示？（核心→常用→高级）
□ 是否预防错误？（影响说明/确认/审计）
□ 空状态是否教学？
□ 是否考虑用户成长路径？
□ 是否建立信任？（审计/AI 依据）
□ 是否上下文感知？（角色/任务动态调整）
□ 是否减少中断？（心流）
□ 是否人机协同？（AI 建议 + 人确认）
```

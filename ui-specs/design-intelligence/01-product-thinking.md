# 设计智能规范 01：产品思维（Product Thinking）

> 最高层规范：任何页面生成之前必须先回答 Who → Why → What → How。
> 组件驱动是代码执行；认知驱动才是产品设计。

## 1. 页面设计第一原则：Who → Why → What → How

生成 UI 前必须回答四个问题（缺一不可）：

| 问题 | 含义 | 输出 |
|---|---|---|
| **Who** 谁使用？ | 用户角色模型（不是"用户"） | 角色名 + 每日任务 + 核心关注 |
| **Why** 为什么打开？ | 用户目的（Jobs To Be Done） | 任务描述（"发现风险订单"而非"看订单列表"） |
| **What** 想看什么？ | Attention Ranking（注意力排序） | 1-3 个最重要信息 + 优先级 |
| **How** 怎么最快完成？ | UX 路径（自动补全/推荐/一键） | 交互模型 |

### 同一页面，四种角色 = 四种设计

| 角色 | 关注 | 页面焦点 |
|---|---|---|
| 销售人员 | 客户、金额、交付日期、成交状态 | 客户视图 + 风险订单 |
| PMC 计划员 | 产能、库存、排产、延期风险 | 产能达成率 + 延期预警 |
| 生产主管 | 今日产量、异常、设备、效率 | 达成率大数字 + 异常优先 |
| 老板 | 收入、利润、风险、趋势 | KPI 大数字 + 风险摘要 |

**规则**：Prompt 无法确定角色时，标注"假设角色 + 待确认"（继承 assessor 的待确认机制），不静默假设。

## 2. JTBD：用户不是要功能，是要完成任务

- ❌ "我要使用搜索功能" → 页面给搜索框
- ✅ "我要快速找到答案" → 自动补全 + 历史记录 + 推荐 + 关联数据展示

**检查**：每个页面问"用户能比之前少几步完成目标？"

## 3. Attention Ranking（注意力排序）

人的注意力有限。生成页面时建立排序：

1. 第一重要：核心指标/异常（大数字、高对比、动效）
2. 第二：趋势/上下文（图表）
3. 第三：详细数据（表格）
4. 第四：次要信息（折叠/次级入口）

**布局规则**：
- 一级信息占 ≥ 40% 视觉空间
- 一个页面最多 **3 个视觉焦点**（全部重点 = 没有重点）
- 普通数据降低视觉权重（更小、更灰、更靠下）

## 4. 异常优先原则（Exception First）

企业系统尤其重要：管理者关注"哪里有问题"而非"所有数据是多少"。

- ❌ 平铺全部状态
- ✅ 异常置顶 + 色编码 + 处理入口（🟢 正常 98% / 🔴 异常 3 / ⚠ 即将延期 5）

## 5. 数据价值决定显示面积（Golden Ratio Layout）

不是所有 Card 一样大：

```
┌──────────────────────────────┐
│     核心指标 98%（大）        │  ← 40%
├────────────┬─────────────────┤
│ 异常 3     │ 趋势图          │  ← 40%
├────────────┴─────────────────┤
│ 详细列表                      │  ← 20%
└──────────────────────────────┘
```

## 6. 页面生成前必须分析（写入 Prompt 的检查链）

```
1. 谁使用？（角色 → 每日任务 → 核心关注）
2. 为什么打开？（任务 → 决策点）
3. 第一眼看到什么？（3 秒规则）
4. 哪些数据突出？（≤3 个视觉焦点）
5. 哪些数据隐藏/折叠？
6. 哪些数据图形化？（指标/趋势/分布）
7. 哪些异常主动提醒？
8. 如何降低认知负担？（自动补全/推荐/上下文）
```

## 7. 角色化页面模式（快速参考）

| 角色 | 首页模式 |
|---|---|
| 老板/CEO | KPI 大数字 + 风险 + 趋势（决策视图） |
| 工程师 | 监控指标 + 实时日志 + 错误追踪 |
| 生产主管 | 今日产量 + 设备状态 + 异常订单 |
| 运营 | 数据趋势 + 增长 + 漏斗 |
| 管理员 | 配置 + 批量操作 + 审计 |

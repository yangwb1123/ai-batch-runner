# Error Recovery & Permission Spec — 错误可恢复 + 权限模型

## 1. 错误分类与用户下一步（禁止统一"操作失败"）

| 错误 | 用户应该怎么办 |
|---|---|
| network | 检查网络后重试 |
| timeout | 查询操作状态，**不要直接重复提交** |
| 401 | 重新登录（刷新令牌后最多重放一次） |
| 403 | 联系管理员或返回 |
| 404 | 返回列表 |
| 409 | 刷新最新数据（并发编辑/版本冲突） |
| 422 | 修正字段或业务条件 |
| 429 | 稍后重试 |
| 500 | 保留输入并重试 |
| partial success | 展示成功与失败项明细 |

统一错误模型（禁止 `catch { message.error('操作失败') }`）：

```ts
type AppError =
  | { type: 'network' }
  | { type: 'timeout'; operationId?: string }
  | { type: 'unauthorized' }
  | { type: 'forbidden'; permission?: string }
  | { type: 'conflict'; latestVersion?: number }
  | { type: 'validation'; fields: Record<string, string> }
  | { type: 'server'; traceId?: string };
```

## 2. 并发编辑与数据版本

保存请求必须携带版本号；409 时：

获取最新版本 → 展示冲突字段 → 允许比较差异 → 覆盖/合并/取消。
**禁止静默覆盖。**

## 3. 权限模型

前端权限只改善体验，不代表安全；服务端必须重新验证。

- 区分：按钮可见性 / 页面访问 / 字段可编辑 / 数据范围 / 接口权限
- 禁止 `role === 'admin'` 散落判断；使用能力标识（`order.approve`）
- 隐藏按钮不能阻止手工调用 API
- 页面/角色/数据范围权限互不等价

## 4. 操作可恢复性清单

- 删除是否可撤销（回收站/确认）
- 批量操作是否可部分重试、报告成功/失败/原因
- 表单草稿；路由离开提示；弹窗关闭保留未提交内容
- 失败后保留筛选条件；上传断点续传；长任务可恢复查询

## 5. 降级与故障隔离

- 分层错误边界（应用/页面/复杂 Widget）：一个图表报错不得白屏整个页面
- 主接口失败 → 缓存/备用接口/只读/隐藏非关键模块
- 非核心功能允许降级（统计图失败 ≠ 订单页不可用）
- 错误后展示 Trace ID，不暴露技术细节

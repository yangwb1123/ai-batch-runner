第四轮与前三轮重叠约 90%。本轮真正新增的是 4 个细节（停滞检测、environment 类熔断、reuse 跳过验证器、多实例竞态）+ diff 注入细化。已逐一核对代码，结论如下。

## 本轮新内容的核验

| 新断言 | 核验结果 |
|---|---|
| **reuse 的陈旧产物不再过验证门禁**（验证器链条只在首次写入时生效一次） | **属实，且是四轮里最便宜的实质正确性修复**。`_filter_reused`（单批）和 `execute_stage` 的"全部复用"短路（`pipeline.py:365` `return [], True`）都直接跳过验证——改了验证器配置或升级了 `cli.py check` 后，续跑场景下门禁确实被悄悄绕过。修复形态很小：reuse 跳过时若存在 `validate` 配置，对已有文件重跑验证器，失败则标记为待重生成 |
| **停滞检测**（连续 K 轮无新增成功 + 失败类别分布不变 → 收敛失败，停止并报告） | 属实缺失。`_run_rounds` 只检查 `round_failed`。且它与熔断正交互补：熔断是任务级，停滞是**批次级**——正好补上"隔离区里只剩 poison 任务时轮循环还在空转"的盲区。实现也很小：每轮记录 (失败任务集, 失败类别集)，与上轮比对 |
| **environment 类熔断**（验证器配置错误应熔断整个阶段而非任务） | 属实且有个隐藏放大器：`_resolve_validators` 把**未知名字当裸 shell 命令**，拼写错误或 gofmt 未安装 → 每任务每轮确定性失败，全部进重试。区分启发式可用：同一验证器对阶段内所有任务以相同退出码/相同 stderr 失败 → environment 类 |
| **两个 7×24 实例跑同一工作目录的竞态** | 属实，全代码无任何锁。最小修复是入口处 O_EXCL 锁文件（startup 时创建，退出删除），3 行 |
| **prompt 字符量 × 模型单价估算 token** | **建议放弃**——上轮已确认 pi 会话文件每条消息带 `usage.totalTokens` 和 `cost`，按 session id 做 usage diff 即得精确计量，不需要启发式估算 |

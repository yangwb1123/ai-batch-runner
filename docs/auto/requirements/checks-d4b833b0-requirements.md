## 1. Summary

The three rglob-based engineering gates — `checks/filesize.py`,
`checks/complexity.py`, `checks/style.py` — discover scan targets with
`root.rglob("*.py")` (or `*{_SUFFIX}`) over the **entire repo tree** with no
directory exclusions. Measured live: **294** `.py` files are scanned, of
which **102 are `build/` copies** (`build/lib/pbatch/*.py`, generated by
setuptools builds) and **3 are `dist/` artifacts**
(`dist/design-intelligence-pack/check-*.py`). The gates stay green today
only through an accident of substring ignore-patterns:

- `build/lib/pbatch/pipeline.py` (**988 lines**) and
  `build/lib/pbatch/runner.py` (**969 lines**) exceed the 500-line filesize
  budget, but are silently exempt because the ignore patterns
  `"pbatch/pipeline.py"` / `"pbatch/runner.py"` are **substrings** of the
  build paths.
- `dist/design-intelligence-pack/check-*.py` (264/317/288 lines) is scanned
  **completely un-ignored** (verified: no pattern matches, no exemption).
  It passes only because it is currently under budget — any regenerated
  artifact over 500 lines fails `make ci` nondeterministically, and gate
  output is polluted with irrelevant paths.

`engineering.yaml:8-11` declares the intended scope: *"quality rules apply
to the code we author here: cli.py, checks/, and anything new"* — generated
directories are not code we author. The fix: exclude generated/artifact
directories at the scan layer (a single shared helper), so all three gates
scan only the authored source tree. `checks/root_files.py` is **not** part
of this direction (see §4 — it does not use `rglob`).

## 3. Root-cause analysis

One structural cause: **scan discovery has no directory-scope filter.**

`run()` in each of the three gates resolves `root = repo_root()` (the
directory containing `engineering.yaml`) and then
`root.rglob("*.py")` — an exhaustive recursive walk that descends into
every directory, including setuptools' `build/` output tree, `dist/`
packages, `.egg-info/`, `.git/`, `__pycache__/`, and `logs/`. The existing
mechanism for exclusions is `ignore_patterns` — **substring matching against
the relative path** (`checks/config.py:is_ignored`, "snaplink semantics").
That mechanism:

- is content-based, not directory-based — it exempts files whose *path
  happens to contain* a pattern, which is exactly why `build/lib/pbatch/…`
  leaks through the `"pbatch/…"` patterns;
- does not stop the scan from *walking* the generated trees (cost + output
  pollution);
- was never designed as a scan-scope declaration — the gate's own comment
  (`engineering.yaml:8-11`) declares the intended scope to be authored code.

Consequence today: the gates are green **by accident of current file sizes**,
not by scope. The `dist/` artifacts are scanned with zero coverage and any
regenerated artifact over budget fails `make ci` nondeterministically;
gate output lists `build/lib/pbatch/…` paths that no maintainer owns.

The fix is a **scan-layer directory exclusion**: one shared helper that
lists `.py` files under the repo root, pruning generated/artifact directory
segments (`build`, `dist`, `*.egg-info`, `.git`, `__pycache__`, `logs`), and
all three `run()` functions discover targets through it. Existence of a
`.py` inside an excluded directory then becomes irrelevant to all three
gates, regardless of size or content.

## 4. Scope boundary

**In scope:**
- One shared scan helper (in `checks/config.py`, the existing shared module)
  that returns the deterministic, sorted list of `.py` files under a root,
  excluding the generated/artifact directory set (R1/R2).
- `checks/filesize.py`, `checks/complexity.py`, `checks/style.py` `run()`
  discover scan targets exclusively through the helper. No other behavior
  of the gates changes.
- New self-tests in `checks/test_filesize.py`, `checks/test_complexity.py`,
  `checks/test_style.py` implementing AC1/AC2 (same `unittest` idiom as the
  existing suites; discovered by both `python -m pytest checks/` and
  `python cli.py check-test`).
- Verification: `python cli.py check` and `python -m pytest checks/` pass
  (AC3, also covered by `make ci`).

**Out of scope (explicitly not part of this direction):**
- `checks/root_files.py` and the root-policy gate — no `rglob` scan, not
  covered by this direction's acceptance. (Direction #3 in the same analysis
  file covers root layering separately.)
- Direction #2 in the same analysis file: per-function complexity
  double-counting / lambda bypass — separate direction.
- Changing `ignore_patterns` in `engineering.yaml` (the existing
  `"pbatch/"`, `".git/"` patterns stay as-is; the scan-layer exclusion
  supersedes their accidental build coverage without touching them).
- Changing the gates' public signatures: `run(files=None)` keeps working;
  an explicit `files` list still bypasses scan discovery and is checked
  with today's exact semantics (including existing substring ignores).
- Excluding `.py` *files* named like directories at the root
  (e.g. `build.py` at repo root is a file, not a directory — scanned as
  today). Exclusion is directory-segment-based (R2).
- Behavior for files passed explicitly that live under excluded dirs
  (e.g. `run(["build/lib/pbatch/transaction.py"])`) — explicit lists are
  unchanged, per above.
- `scripts/check-*.py` gates (`uicheck` etc.) and `quality.py` — different
  scanners, separate modules, not cited by this direction.

## 5. Requirements

**R1 (scan scope) — generated/artifact directories are excluded from scan
discovery for all three rglob gates.**
`checks/filesize.py:run()`, `checks/complexity.py:run()`, and
`checks/style.py:run()` must discover scan targets through a single shared
helper (e.g. `checks/config.py:scan_files(root, suffix=".py")`) instead of
calling `root.rglob(...)` directly. The helper returns the sorted list of
paths with suffix `.py` under `root`, excluding every path whose relative
parent segments include any name in the default exclusion set. Default
exclusion set (directory **segment names**, matched at any depth):
`build`, `dist`, `.git`, `__pycache__`, `logs`, and any segment ending in
`.egg-info` (covers `ai_batch_runner.egg-info`). Segment-name matching, not
substring matching: `src/build-tools/x.py` and `mylogs/x.py` are **not**
excluded; `subproject/build/x.py` **is** excluded. The helper must not
descend into excluded directories at all (prune before walking), so the
scan is both correct and cheap.

**R2 (determinism and ordering) — scan behavior is deterministic and
compatible.**
The helper returns paths in sorted order (same ordering as today's
`sorted(root.rglob(...))`), relative to the same `repo_root()` semantics
(`checks/config.py:repo_root()` — the directory containing
`engineering.yaml`). Excluded-set membership is decided purely by directory
segments **relative to `root`**: a directory named `build` outside `root`
never matters. `run()` signatures stay `run(files: list = None)`; when
`files` is given, scan discovery is skipped entirely and every path is
checked exactly as today (R3). The existing `ignore_patterns` /
`exemptions` logic in `check_file`/`check_tree`/`check_text` is untouched —
the scan-layer exclusion is additive.

**R3 (compatibility) — existing behavior, tests, and gate output for
non-generated paths are unchanged.**
All existing tests in `checks/test_filesize.py`, `checks/test_complexity.py`,
`checks/test_style.py` pass unmodified (they use explicit `files` lists or
direct `check_file` calls, which never go through scan discovery). Gate
output for authored files (including the existing `WARN:` lines from style)
is byte-identical. `checks/root_files.py` and `engineering.yaml` are not
modified.

**R4 (regression tests) — `checks/test_*.py` gain the AC1/AC2 tests.**
New tests follow the existing `unittest.TestCase` idiom in those files and
are hermetic: they build a temporary root tree and redirect discovery by
monkeypatching the module-bound `repo_root` (and, where needed, `get_config`)
names inside `checks.filesize` / `checks.complexity` / `checks.style` (the
modules bind these via `from checks.config import ...`, so the patch target
is the gate module's namespace — no repo mutation, no reliance on the real
`build/` directory). Exact test plan in §7. The tests must be runnable by
both `python -m pytest checks/` and `python cli.py check-test`.

**R5 (optional, non-blocking) — documentation note.**
One line in `checks/README.md` (or the `engineering.yaml` header comment)
noting that scan discovery excludes generated/artifact directories
(`build/`, `dist/`, `*.egg-info/`, `.git/`, `__pycache__/`, `logs/`) so
"code we author" stays the gate scope. Not required by any acceptance
check; safe to skip.

## 6. Acceptance criteria (supplied, made testable)

The three supplied acceptance checks are preserved verbatim in intent; each
is pinned to deterministic assertions automatable in `checks/test_*.py`.

**AC1 — new unit test in `checks/test_filesize.py`: a 600-line `.py` placed
under `build/` does not fail `run()`.**
> New unit test in checks/test_filesize.py: a 600-line .py placed under
> build/ does not fail run()

Testable form (one test, `test_build_dir_excluded_from_run`):

- Build a temp root: `tmp/build/oversized.py` (600 valid-Python lines,
  e.g. comment lines — must exceed the default 500-line budget),
  plus `tmp/ok.py` (5 lines).
- Monkeypatch `checks.filesize.repo_root = lambda: tmp` and
  `checks.filesize.get_config` to return a config whose `filesize.max_lines`
  is 500 (default), so the 600-line file is the only over-budget input.
- Assert `filesize.run()` returns `0` (build copy excluded ⇒ no failure).
- Negative control in the same test: move the 600-line file to
  `tmp/src/oversized.py` (a non-excluded dir), assert `run()` returns `1`
  — proving the exclusion, not a broken budget, is what passes.

**AC2 — new unit tests: `run()` scan lists never contain paths under
`build/`, `dist/`, `*.egg-info/`, `.git/`, `__pycache__/`, `logs/` (for all
three gates).**
> New unit test: filesize/complexity/style run() scan lists never contain
> paths under build/, dist/, *.egg-info/, .git/, __pycache__/, logs/

Testable form (one test per gate, sharing one temp-tree fixture; in
`checks/test_filesize.py`, `checks/test_complexity.py`,
`checks/test_style.py` respectively, e.g.
`test_run_scan_excludes_generated_dirs`):

- Build a temp root containing one valid `.py` file under **each** of the
  six excluded directory kinds: `build/`, `dist/`, `ai_batch_runner.egg-info/`
  (or any `*.egg-info/` segment, exercised at depth, e.g.
  `vendor/pkg.egg-info/`), `.git/`, `__pycache__/`, `logs/` — plus one
  ordinary `src/ok.py`. Files must be syntactically valid Python (the
  complexity gate `ast.parse`s them) and short (no size/style budget trips).
- Monkeypatch the gate module's `repo_root` to the temp root; call
  `run()`.
- Assert `run()` returns `0` **and** that the scan list it used (assert
  directly against the shared helper, e.g. `scan_files(tmp)`, or via a
  captured list) contains exactly `src/ok.py` — never a path under any of
  the six excluded kinds, at any depth.
- For filesize only, additionally assert that a 600-line file under
  `logs/` (as the "any excluded dir" representative) does not fail `run()`
  — redundant with AC1's mechanism, but pins the full set.

**AC3 — repository gates stay green.**
> python cli.py check and python -m pytest checks/ both still pass

Testable form: run both commands; each must exit 0 on the repository.
`python cli.py check` exercises all four gates (filesize, complexity,
root-policy, style) end-to-end on the real repo; `python -m pytest checks/`
collects and passes the existing suites plus the new AC1/AC2 tests (this is
also covered by `make ci`, whose `check`/`self-test` targets run
`python cli.py check` and the checks/ unittest suites).

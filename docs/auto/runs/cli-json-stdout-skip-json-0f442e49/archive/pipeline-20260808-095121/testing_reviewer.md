## 2. AC3 negative-control audit — arithmetic error in the label; AC2 is vacuous

Simulated union vs naive-replace against the exact AC3 fixture (`src/a.tsx`, `scratch/b.tsx`, `e2e/c.tsx`):

- `--skip e2e`: union = **2**, replace = **2** — **no discrimination**. The design doc F2 row and the test comment ("replace-implementation yields 3") are wrong: under replace, `excludes = {"e2e"}` and e2e is *the skip value itself*, so it stays excluded either way. The "3" only materializes when the skip value is *not* in `DEFAULT_EXCLUDES`.
- `--skip scratch`: union = 1, replace = 2 (replace drops the defaults and re-scans `e2e/`) — **this is the line that actually catches replace**, and the test does assert 1, so the AC3 test *as a whole* remains a valid negative control. Just the label/comment is wrong.
- `--skip scratch,e2e`: union = 1, replace = 1 — no discrimination.
- **AC2 (backend) is fully vacuous against replace**: its fixture (`src/a.go`, `scratch/b.go`) has no file under a default-excluded segment; all four assertions (2/1/2/2) pass identically under replace (verified by simulation). A backend-only replace bug would sail through AC2 and be caught only by AC3's scratch line. Fix: add `tests/x.go` to AC2's fixture → `--skip scratch` becomes union=1 vs replace=2 → discriminates (verified numerically). Also correct the `--skip e2e` comment (it's an idempotence/default-retention pin, not a replace trap).

## 3. `test_health_main_json_shape` flake + F5 oracle — isolation required; F5 rejected

- **The flake is real and mechanism-proven**. `assert health.health_main(["--json"]) == 0` requires `healthy == True` ⇔ quality==0 ∧ all 3 checkers==0 ∧ tests>0 — all on the **live tree**. In-process simulation (no files touched): `_checker_violations → -1` (any transiently broken checker) or `_quality_violations → 4` (a campaign's intermediate code) both flip `health_main` to exit 1 → the test fails. I watched the checker sources change mid-audit — a checker run 2 seconds after a half-written write gives `json.loads("") → ValueError → -1`. This is a direct flake under concurrent campaigns, exactly as the QA lead said. It's not lock-blocked (spawns checkers directly, not pi-batch) — it's purely live-tree-state-dependent.
- **F5 (`assert expected == 0`) is redundant and should be rejected**: backend exit-0 ⟺ 0 violations (verified: ok path exit 0 → total 0; skipped → 0; empty → exit 1). The existing `assert direct.returncode == 0` in `test_health_checker_plain_json_contract` already implies `expected == 0`; the added assertion would only hard-pin live-tree greenness — i.e., add flake surface with zero new coverage. The walk-up trap is also live here: `/home/u1` is manifest-free today (sibling repos `aero-id/`, `snaplink/`, `snaplink-sso/` have their own go.mods but are not ancestors — verified), but a go.mod at ROOT or `/home/u1` would flip the backend checker from skipped→scanned. That dependency already exists via `returncode == 0`; F5 would make it *explicit* rather than fixing it.
- **Isolation recommendation**: monkeypatch the three live-leaf functions in the shape test — `health._checker_violations`, `health._quality_violations`, `health._count_tests` — to deterministic values (same pattern as `test_health_governance_counts_shape`'s `monkeypatch.setattr(health, "ROOT", …)`), leaving `_spec_counts`/`_governance_counts` real (values unasserted, so campaigns writing `.pi-batch/devices` can't break it). This eliminates all 4 subprocesses and the green-tree dependency while still exercising `health_report`/`health_main`/JSON shape (~1.4s → ~0.3s). Optionally keep one tolerant live smoke (`healthy in {True, False}`) elsewhere if end-to-end wiring coverage is wanted. For `test_health_checker_plain_json_contract`, the live-subprocess equality is its purpose; hardening options are a bounded retry on transient `-1`/returncode, or a fixture ROOT — prefer retry, keep the source-string guards.
- **Settle-then-rerun remains mandatory**: the 102/102 green is against a moving tree; the concurrent direction's test was fixed by its owner, but cross-direction conflicts (this one resolved by mutual accommodation — exit-2 is now family behavior both tests assume) need a full `make ci` after campaigns finish.

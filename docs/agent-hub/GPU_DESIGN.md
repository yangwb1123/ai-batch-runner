# GPU 计算增量设计

本轮在已有 CPU/内存计算任务中增加 NVIDIA CUDA 物理 GPU 的发现、按卡数和
每卡可用显存筛选、控制面准入和 Runner 执行前复核。保持单 Runner 单任务执行槽。
AMD、Apple GPU、MIG、容器设备隔离及真实硬件性能验收不属于本轮实现。

## 持久化设计

| 模型 | 增量及约束 |
|---|---|
| 领域请求 | `resources.gpu_count` 为 0–16；`gpu_memory_bytes` 为每卡最低显存需求，0–1 TiB；无 GPU 请求不得要求显存 |
| Hub 持久记录 | 沿用 `hub_compute_tasks` 请求 JSON 与数据 JSON；仅正数 GPU 请求保存这两个键，旧 CPU 请求的规范化值及幂等比较保持不变 |
| Fabric 持久记录 | 复用现有任务快照；控制面选择 GPU UUID 并保存分配，不接受调用者指定分配；重复提交返回原任务与原分配 |
| API DTO | 设备返回有界 GPU 型号、UUID、总/可用显存、探测状态和可调度状态；任务返回需求与控制面确认的分配，凭据不进入 DTO |
| 证据 | 任务结果记录实际 GPU 分配；沿用现有摘要、fencing 和离线证据机制，不把显存需求称为 OS 限额 |

不新增表、主键或唯一约束；现有租户/用户幂等唯一键和任务分页索引保持不变。
Hub 和 Fabric 的 CPU 请求迁移无需重写历史记录。新旧控制面及 Runner 用显式
GPU 能力标记区分；缺失标记、失败/过期探测、显存不足均不可派发 GPU 任务。
已有 CPU 任务不依赖 NVIDIA 驱动或 GPU 探测成功。

设备仍由管理员审批，Hub 仍按 tenant、源会话和 compute_instances 权限筛选。
控制面在现有任务锁内再次验证资源与执行槽；Runner 在启动命令前复核本机 GPU。
CUDA 设备可见性只约束遵守 CUDA 环境的应用，不是恶意本地程序的设备访问沙箱。

## 验证要求

覆盖旧 CPU 请求幂等、GPU 请求边界、缺失/过期/异常探测、逐卡显存筛选、权限
隔离、锁内准入、分配持久恢复、确认丢失、执行前变化拒绝、子进程设备环境及
取消回收。CLI、TUI 和 Console 使用同一请求边界。设备探测可用确定性替身；
有无真实 GPU 硬件和是否运行 CUDA 工作负载必须在最终验证记录中单独说明。
